# 役割分担とタスク一覧

最終更新：2026-11-19

## 方針
- **あなた（開発者）**：決めること、アカウントや外部サービスの操作、日本語ネイティブとしての校正、実機確認。
- **Claude**：コード、ツール、文書の下書き、翻訳の下訳、あなたの校正コメントへの対応。
- ボトルネックは**問題の校正**と **Play のクローズドテスト（12 人 × 14 日）**。この 2 つは今すぐ並行で始める。

## 公開までの流れ
```
[今すぐ並行]  A. 名前と ID を決める ─┬─> B. Play Console 登録 ─> C. テスター 12 人集め ─┐
                                    └─> F. RevenueCat と商品 ────────────────────┤
              D. 120 問の校正（CSV） ─> Claude：修正と解説の翻訳 ─────────────────┤
                                                                                └─> クローズドテスト 14 日 ─> 本番公開
```

## あなたの宿題（優先順）

### A. 決める（10 分）— 最優先。B と F が待っている
- [ ] **Application ID**（例：`com.<あなたの屋号>.jftprep`）。Play に登録すると変更できない。決まったら Claude に伝える（今は仮に `com.nihongoprep.jft_prep`）。
- [ ] **アプリ名**。案は「JFT-Basic Prep: Japanese Test」。
  - 試験名を含むアプリ名は、なりすましとして審査で指摘される可能性がある。
  - 説明文には「国際交流基金とは無関係」と明記してある。
  - 指摘されたときの代案（例：「Nihongo Work Prep」）も考えておくと安心。
- [ ] **価格**：年額 6〜8 ドル（仮説）と月額。月額を置くかどうかも決める。
- [ ] **連絡先メール**（ストアとプライバシーポリシーに載せる。公開用のアドレス推奨）。

### B. Google Play Console（30 分〜。審査や本人確認に数日かかることがある）
- [ ] デベロッパー アカウント（未登録なら登録費 25 ドルと本人確認）。
- [ ] アプリを作成し、`store/listing.md` の英語版を入力する。
- [ ] アイコン `store/icon-512.png` とフィーチャーグラフィック `store/feature-graphic.png` をアップロードする。
- [ ] データセーフティ：`store/data-safety.md` の回答案を入力する。
- [ ] プライバシーポリシー：`store/privacy-policy.md` の `[ ]` を埋めて公開 URL を用意する。
  - 公開先の例：Google サイト、Notion の公開ページ、GitHub Pages（公開リポジトリ）。
- [ ] アップロード鍵を作り、`android/key.properties` を用意する（手順は README）。

### C. クローズドテストのテスター集め（時間がかかるので最優先で着手）
- [ ] 個人アカウントなので「12 人以上が 14 日間連続でオプトイン」が必要。余裕を見て 15〜20 人を集める。
- [ ] 方針：**ランサーズ（タスク形式）で有償募集する**。掲載前に、規約でアプリのテスト依頼が認められているかを確認する。
- [ ] 募集文、テスター向けの手順書、感想フォーム案は [`docs/testers.md`](testers.md) にある。
- [ ] 感想フォームの問 5（Premium を買いたいか）は、価格の仮説を検証するデータにもなる。

### D. 問題の校正（本丸。1 問 1〜2 分として 120 問で 2〜4 時間）
1. Claude が渡す `review.csv` を Google スプレッドシートか Excel で開く。
2. 各行で、問題文、選択肢、正解、解説（英語）、ふりがなの読みを確認し、その場で直す。
3. 問題なければ `ok` 列に `1` を入れる。書き直しの依頼や疑問は `comment` 列に書く。
4. 保存した CSV を Claude に渡す（または `python3 tool/review_sheet.py import assets/questions.json review.csv`）。
- ふりがなは自動で付けた下書き。数字のあとの読み（3階＝がい、10分＝ぷん など）は特に確認する。
- `ok` を付けた問題だけがリリース版に出る。各分野 30 問そろわなくても、校正済みの分だけで出すことはできる。

### E. 実機（Pixel）での確認（30 分）
- [ ] テスト版 APK（下書きも全問出る版）を入れて全画面を触る。
  ```bash
  flutter run --release --dart-define=INCLUDE_DRAFTS=true --dart-define=UNLOCK_ALL=true
  ```
- [ ] 聴解の音声：日本語の音声データが入っているか、読み間違いや不自然なところがないか。
- [ ] UI 言語をネパール語とミャンマー語に切り替え、文字化けしないか。
- [ ] 気になった点は箇条書きで Claude へ。

### F. 課金の設定（1 時間。B が終わってから）
- [ ] Play Console でサブスク商品を 2 つ作る（年額と月額）。国別価格も設定する。
- [ ] RevenueCat：プロジェクト作成、Play との連携（サービスアカウント）、Entitlement `premium`、Offering。手順は README。
- [ ] 公開 SDK キー（`goog_...`）をビルド時に渡す。秘密鍵ではないが、リポジトリには入れない。
- [ ] 内部テストトラックで購入、解約、復元を試す（ライセンステスターのアカウントで）。

### G. 計測（任意。公開判断の指標に必要）
- [ ] 撤退基準（30 日で 1,000 インストール、転換率 1%）を測るなら Firebase が要る。
  - Firebase プロジェクトを作り、`google-services.json` を Claude に渡す（リポジトリに入れてよい）。
  - Play Console の統計（インストール数）と RevenueCat（転換率）だけで足りるなら不要。

### H. 翻訳のネイティブ確認（任意。テスター集めと一緒に）
- [ ] `lib/l10n/app_id.arb` などを各言語のネイティブに見てもらう。
- [ ] 確認が済んだ言語は Claude に伝える（「機械翻訳」の表示を外す）。

### I. ブランチのマージ
- [x] `main` にマージ済み（2026-11-19）。
